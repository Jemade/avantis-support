# ADR 007: AI Architecture & Grounded Retrieval

## Status
Accepted

## Context
The legacy Gemini chat assistant in `gemini_service.js` directly received raw system prompts containing device strings. While it attempted to instruct the model not to hallucinate, there was no structured tool-calling architecture, no dynamic grounding via authorized API tools, and no mechanism for IT technicians to leverage RAG across support runbooks. Furthermore, exposing raw shell execution directly to an LLM is a catastrophic security vulnerability.

## Decision
We enforce a **Deterministic Tool-Augmented & Strictly Grounded AI Architecture**:
1. **Core Principle**: AI models never possess direct shell execution privileges. The LLM acts purely as an analytical and conversational reasoning engine interacting with the system through an **Authorized System Tool Gateway**:
   ```
   User / Technician
          │
          ▼
   AI Assistant
          │
          ▼ (Function Calling Intent)
   Authorized Tool Gateway (Deterministic C# APIs)
   - get_device_inventory()
   - get_current_health()
   - get_recent_events(limit, severity)
   - get_diagnostic_results(runId)
   - get_performance_history(timeframe)
   - search_knowledge_base(query, tenantId)
          │
          ▼
   Evidence Payload returned to LLM
          │
          ▼
   Grounded Natural Language Explanation + Citations
   ```
2. **Provider Abstraction (`ILLMProvider`)**:
   * Support pluggable providers (Google Gemini, OpenAI, Azure OpenAI, Anthropic, or Local Ollama/vLLM) configured via environment variables.
   * Resilient fallback handling: if an external LLM is offline or unconfigured, the UI clearly displays `AI Provider Unavailable` and displays deterministic evidence cards rather than fabricating responses.
3. **Tenant-Isolated Knowledge RAG**:
   * Knowledge base documents (runbooks, error codes, hardware specs) are indexed with vector embeddings and filtered strictly by `TenantId` at query time to prevent cross-tenant data leakage.
4. **Auditability & Cost Governance**:
   * Every AI interaction logs prompt tokens, completion tokens, latency, invoked tools, and evidence citations in `ai_conversations` and `ai_audit_logs`.

## Consequences
### Positive
* Zero possibility of LLM prompt injection executing arbitrary PowerShell commands.
* Answers are strictly backed by verifiable telemetry and knowledge base citations.
* Pluggable across cloud and air-gapped enterprise environments.

### Negative
* Additional latency for function calling round-trips.
